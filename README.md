# stockroom

本地多仓库存台账命令行工具。使用 TypeScript + Node.js 24 编写，无外部运行依赖，
数据以单个 JSON 文件保存在本地；支持指定数据目录，不同目录互不影响。

## 运行环境

- Node.js 24（直接执行 `.ts`，无需编译或安装依赖）

## 快速开始

```sh
# 登记商品
node app.ts -d ./data product add P1 螺丝
node app.ts -d ./data product add P2 螺母
node app.ts -d ./data product list

# 入库 / 出库 / 跨仓调拨（每单可含多个 --item，同商品重复明细自动合并）
node app.ts -d ./data in D1 --wh W1 --item P1:10 --item P2:3
node app.ts -d ./data out D2 --wh W1 --item P1:4
node app.ts -d ./data transfer D3 --from W1 --to W2 --item P1:2 --item P1:3

# 整单盘点校正（先核对账面再按实盘校正；同商品重复明细拒绝）
node app.ts -d ./data count C1 --wh W1 --item P1:6:8 --item P2:3:3

# 整单冲销已成功的入库/出库/调拨/盘点/到货单（独立冲销单编号 + 被冲销原单编号）
node app.ts -d ./data reverse R1 --orig D1
node app.ts -d ./data reverse R2 --orig C1

# 采购单：登记（不改库存）、分批到货、进度查询
node app.ts -d ./data po add PO1 --supplier 华东五金 --wh W1 --item P1:10 --item P2:5
node app.ts -d ./data receive RC1 --po PO1 --item P1:4
node app.ts -d ./data receive RC2 --po PO1 --item P1:6 --item P2:5
node app.ts -d ./data po show PO1
node app.ts -d ./data po list
node app.ts -d ./data reverse R3 --orig RC1   # 整单冲销到货：扣回库存并减少有效到货量

# 整批导入有序单据列表（按顺序生效，整批成败一致）
node app.ts -d ./data import --file ./docs.json

# 余量查询（指定仓库或各仓）
node app.ts -d ./data balance P1
node app.ts -d ./data balance P1 --wh W2

# 流水查询（按商品/仓库/采购单，按提交顺序，含冲销反向变动与原单冲销状态）
node app.ts -d ./data flow --product P1
node app.ts -d ./data flow --wh W2
node app.ts -d ./data flow --po PO1
```

## 命令行入口与调用说明

- 无参数、`--help`、`-h`：显示应用名与完整帮助，退出码 0。
- 未知命令或非法参数：向标准错误报错，退出码 2。
- 业务拒绝（重复编号、缺货、溢出、单据内容冲突、非法冲销等）或数据损坏/保存失败：
  向标准错误报错，退出码非 0（1）。
- 全局选项 `-d, --data <目录>` 指定数据目录，默认 `./.stockroom`；
  数据文件为目录内的 `stockroom.json`，首次写入时自动创建。
- 也可执行 `npm link` 后使用 `stockroom` 命令（等价于 `node app.ts`）。

## 主要规则

- 商品编号、名称、单据编号、仓库标识均去除首尾空白后使用，不能为空；标识区分大小写。
- 商品编号唯一，重复登记被拒绝且不覆盖原资料。
- 入库增加目标仓余量，出库减少来源仓余量；调拨同时减来源仓、增目标仓，两仓不能相同。
- 数量必须为正安全整数；同单同商品明细先合并，再校验足量与安全整数上溢。
- 任一明细不合法则**整单拒绝**，所有库存保持原状（不部分生效）。
- 入库/出库/调拨/盘点/到货/冲销单据编号在同一数据目录内共用全局唯一编号空间，
  采购单编号独立（可与单据同名）：相同业务内容重复提交返回原结果、不重复变动；
  同编号不同内容或不同业务拒绝；失败提交不占用编号。
  去重记录、冲销关系、采购进度与库存、流水、结果一起持久化。
- 流水记录单据编号、类型、涉及仓库、数量及变动前后余量；调拨/冲销调拨两端可凭同一
  单据编号追溯；盘点/冲销盘点流水记录账面量、实盘量与差额（含零差额），差额正负及
  零变动与前后余量一致；到货/冲销到货流水记录所属采购单编号，可按采购单追溯。

## 采购单与分批到货

- 登记：`po add <采购编号> --supplier <供应商名称> --wh <收货仓> --item <商品编号:数量> [...]`。
  采购单含编号、供应商名称、收货仓与**已登记商品**的订购量（至少一项，正安全整数，
  同商品明细先合并再查溢出，明细顺序无关）。登记**不改库存**，成功后**不可修改**。
- 采购编号独立于库存单据编号空间，可同名；标识与名称去首尾空白后非空、区分大小写，
  `__proto__` 等名称可正常使用。同号同内容重放返回原登记结果、不重置进度；
  同号不同内容拒绝。
- 到货：`receive <到货单编号> --po <采购编号> --item <商品编号:数量> [...]`。
  到货单号与库存单据、冲销单共用编号空间；按采购单的收货仓分批入库，**仅收单内商品**，
  各商品未冲销累计到货不得超过订购量；其他库存业务（入出库、调拨、盘点）不改变采购进度。
  任一明细非法、超收或库存溢出**整单拒绝**；成功同时更新库存与进度，输出本次数量、
  库存前后量、累计及待到货量。
- 到货幂等：同号同采购同合并数量重放返回原结果，即使已收齐、库存变化或该到货已冲销
  也不再生效；同号不同内容或其他业务（如普通入库同号）拒绝，普通入库不可事后绑定采购；
  失败不占编号。
- 冲销到货：`reverse <冲销单编号> --orig <到货单编号>` 整单冲销，从**当前**收货仓扣回
  原数量并减少有效到货量（已收齐的采购单重新变为待收），不撤销后续业务。任一商品余量
  不足整单拒绝，不改进度或冲销关系，同号可重试；每张到货最多冲销一次，冲销单不可冲销；
  原到货及成功冲销重放均返回原结果，不重复变动。
- 查询：`po show <采购编号>` 显示供应商、收货仓、各商品订购/有效到货/待到货量、
  未到货/部分到货/收齐状态及到货单与冲销关联；`po list` 汇总全部采购单状态；
  `flow --po <采购编号>` 追溯该采购单的到货与冲销流水。

## 整单盘点规则

- 命令：`count <单据编号> --wh <仓库> --item <商品编号:预期账面量:实盘量> [...]`，
  每张盘点单针对一个仓库、至少一种已登记商品；两种数量均为非负安全整数，
  同商品重复出现拒绝（不像入出库那样合并）。
- 首次提交先逐项核对当前余量与预期账面量（未发生变动的商品仓库组合账面量为零），
  任一不符**整单拒绝**并说明冲突商品及当前量；全部相符才把列出的商品校正为实盘量，
  未列出的商品及其他仓库不变。
- 差额 = 实盘量 - 账面量，可增、可减、可为零；全零差额仍记为成功单据并逐项追加流水。
- 幂等：同编号同内容（明细顺序无关）重放只返回原提交结果，即使余量已改变或盘点已
  被冲销也不再核对、不再生效；同编号不同内容或其他业务拒绝；失败不占用编号，
  调整输入后可重试。
- 成功输出各商品的预期账面量、实盘量、差额及校正前后余量。

## 整单冲销规则

- 命令：`reverse <冲销单编号> --orig <原单编号>`，只能冲销**已成功**的原始入库、
  出库、调拨、盘点、到货单；原单不存在、冲销单本身、已被成功冲销的原单均不能产生新的冲销，
  每张原单最多成功冲销一次。
- 冲销在**当前余量**上应用原单的相反变动，不恢复为原单提交前的绝对余量，也不删除
  原单之后的其他业务：
  - 冲销入库：从原目标仓扣回数量；
  - 冲销出库：向原来源仓补回数量；
  - 冲销调拨：从原调入仓扣回、向原调出仓补回；
  - 冲销盘点：在当前余量上减去原盘点差额（不恢复原账面绝对值）；零差额不改余量，
    但仍记录冲销关系与流水；
  - 冲销到货：从当前收货仓扣回原数量，并减少采购单有效到货量（收齐的采购单重新待收）。
- 数量取原单同商品合并后的明细。任一商品扣回不足，或补回后余量超出安全整数范围，
  或盘点冲减后为负/溢出，则整单拒绝、所有仓库与商品保持原状；失败不占用冲销单编号、
  不标记原单，条件改善后可用同一编号重试。
- 幂等：成功冲销的同编号、同原单请求重放，返回原冲销结果，即使余量已变化也不再
  变动；同编号改指其他原单或其他业务一律拒绝。原库存单据冲销后按原内容重放，仍只
  返回它最初的提交结果，不会重新生效。
- 成功输出各明细数量及操作前后余量，并在流水中追加反向变动条目（关联原单与冲销单
  编号）；`flow` 按商品/仓库可看到完整历史、原流水顺序及原单的冲销状态。
- 库存、流水、冲销关系和重放结果一起保存，保存（临时文件原子替换）成功后才报告
  成功，重启后全部限制仍成立；业务拒绝或保存失败均不改变已提交状态。

## 整批导入

- 入口：`import --file <单据列表.json>`（与其他命令一样可配合 `-d/--data` 指定数据目录）。
- 文件为 UTF-8 JSON：根节点必须是**有序单据对象数组，至少一项**；按数组顺序处理，
  新单据以此前各项生效后的余量核对并计算，流水中的先后顺序与列表顺序一致。
- 仅允许七种业务，字段如下（所有标识去除首尾空白后非空、区分大小写）：

  | 业务 | type | 必需字段 | 明细字段 |
  | --- | --- | --- | --- |
  | 入库 | `in` | `id`、`wh`、`items` | `product`、`qty` |
  | 出库 | `out` | `id`、`wh`、`items` | `product`、`qty` |
  | 调拨 | `transfer` | `id`、`from`、`to`、`items` | `product`、`qty` |
  | 盘点 | `count` | `id`、`wh`、`items` | `product`、`expected`、`actual` |
  | 采购 | `po` | `id`、`supplier`、`wh`、`items` | `product`、`qty` |
  | 到货 | `receive` | `id`、`po`、`items` | `product`、`qty` |
  | 冲销 | `reverse` | `id`、`orig` | 无（数量取原单合并后的明细） |

- 商品必须已登记；入出库、调拨、采购及到货的 `qty` 为正安全整数，同商品明细先合并再校验；
  盘点的 `expected`/`actual` 均为非负安全整数，同商品重复出现拒绝；调拨两仓不能相同。
- 后项可以使用前项入库所得库存；盘点核对的是此前各项之后的账面量；采购单登记不改库存、
  不可修改；到货按采购单收货仓入库并更新进度，仅收单内商品、超收整批拒绝；冲销可指向
  导入前已成功的原单或列表中此前的新原单，**尚未出现且未保存的原单不可引用**；
  冲销到货同样减少有效到货量；冲销单不可冲销，每张原单最多冲销一次。
- 编号与单条命令共用唯一空间（采购编号独立），不产生批次编号：导入前已有或本列表此前出现的
  “同编号同内容”项均只返回原结果，不重新核对库存、不追加流水——即使原单已冲销
  也不重新生效。普通单据比较类型、仓库及合并后的商品数量（明细顺序无关）；盘点
  比较仓库及各商品两种数量；采购比较供应商、收货仓及订购量；到货比较采购编号及合并
  数量；冲销比较原单编号。同编号不同内容或不同业务整批拒绝。
- 整批成功须全部项通过，有新生效单据时整批一次性保存；**全部重复时不改写数据**。
  任一项格式不合法、缺货、超收、账面冲突、溢出、编号冲突或非法冲销，整批拒绝并指出
  位置（第几项）和原因：此前已保存的单据不撤销，本批新库存、采购进度、流水、编号与冲销
  关系均不保留，纠正后可复用这些新编号。
- 文件无法读取、已有数据损坏或保存失败均不改变已提交状态，也不报告部分成功。
  文件格式或参数错误报标准错误、退出 2；业务拒绝及读写失败退出 1。
- 成功时按列表顺序逐项输出编号、“首次生效/重复（导入前已存在/本批此前已出现）”
  状态及对应提交结果；新流水按列表顺序追加，保留既有历史与冲销关联，可通过
  `flow` 读回，重启后查询、去重与冲销限制仍成立。

最小示例文件 `docs.json`（仅一项即可导入）：

```json
[
  {"type": "in", "id": "D1", "wh": "W1", "items": [{"product": "P1", "qty": 10}]}
]
```

五种业务齐备的示例（另含采购与到货）：

```json
[
  {"type": "in",       "id": "D1", "wh": "W1",
   "items": [{"product": "P1", "qty": 10}, {"product": "P1", "qty": 2}]},
  {"type": "out",      "id": "D2", "wh": "W1",
   "items": [{"product": "P1", "qty": 4}]},
  {"type": "transfer", "id": "D3", "from": "W1", "to": "W2",
   "items": [{"product": "P1", "qty": 3}]},
  {"type": "count",    "id": "C1", "wh": "W2",
   "items": [{"product": "P1", "expected": 3, "actual": 2}]},
  {"type": "po",       "id": "PO1", "supplier": "华东五金", "wh": "W1",
   "items": [{"product": "P1", "qty": 10}]},
  {"type": "receive",  "id": "RC1", "po": "PO1",
   "items": [{"product": "P1", "qty": 4}]},
  {"type": "reverse",  "id": "R1", "orig": "D3"}
]
```

## 数据兼容与安全

- 旧版数据文件（无冲销、采购字段）无需重新登记或导入即可直接读写，原有单据的去重记录与
  提交结果继续生效，旧入库单不会被推断为到货；首次发生冲销或登记采购单后自动补齐相应字段。
- 所有记录容器使用 null 原型对象，`constructor`、`__proto__`、`toString` 等名称可
  正常作为商品、仓库、单据编号使用，不会串改其他记录或保存非法余量。
- 数据文件损坏、无法读取或结构校验不通过时明确报错退出，不会当作空库覆盖。
