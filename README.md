# stockroom

本地多仓库存台账命令行工具。使用 TypeScript + Node.js 24 编写，无外部运行依赖，
数据以单个 JSON 文件保存在本地；支持指定数据目录，不同目录互不影响。

## 运行环境

- Node.js 24（直接执行 `.ts`，无需编译或安装依赖）

## 快速开始

```sh
# 登记商品
node app.ts -d ./data product add P1 螺丝
node app.ts -d ./data product add P2 螺母
node app.ts -d ./data product list

# 入库 / 出库 / 跨仓调拨（每单可含多个 --item，同商品重复明细自动合并）
node app.ts -d ./data in D1 --wh W1 --item P1:10 --item P2:3
node app.ts -d ./data out D2 --wh W1 --item P1:4
node app.ts -d ./data transfer D3 --from W1 --to W2 --item P1:2 --item P1:3

# 整单盘点校正（先核对账面再按实盘校正；同商品重复明细拒绝）
node app.ts -d ./data count C1 --wh W1 --item P1:6:8 --item P2:3:3

# 采购单登记（不改库存）与分批到货、部分退货、进度查询
node app.ts -d ./data po register PO1 --supplier 华东五金 --wh W1 --item P1:10 --item P2:5
node app.ts -d ./data arrival A1 --po PO1 --item P1:4 --item P1:3   # 同商品先合并为 7
node app.ts -d ./data arrival A2 --po PO1 --item P1:3 --item P2:5   # 可分次、可部分到货
node app.ts -d ./data cancel X1 --po PO1 --item P2:5                # 取消未到货数量（只减少待收承诺，不改库存）
node app.ts -d ./data return T1 --arrival A1 --item P1:2            # 部分退货：从原收货仓扣减，退回后等待补收
node app.ts -d ./data po show PO1

# 采购待收转单：把原采购单的部分待收转给新的目的采购单（重排供应商/收货仓，不改库存）
node app.ts -d ./data po-transfer F1 --orig PO1 --dest PO2 --supplier 华南五金二厂 --wh W2 --item P1:2
node app.ts -d ./data arrival A4 --po PO2 --item P1:2              # 目的单可按普通采购到货
node app.ts -d ./data reverse R6 --orig F1                         # 整单冲销转单（须目的单仍全量待收）
node app.ts -d ./data po show PO2
node app.ts -d ./data po list

# 整单冲销已成功的入库/出库/调拨/盘点/到货/取消/退货单（独立冲销单编号 + 被冲销原单编号）
node app.ts -d ./data reverse R1 --orig D1
node app.ts -d ./data reverse R2 --orig C1
node app.ts -d ./data reverse R3 --orig A1   # 冲销到货：扣回库存并重开待到货量（不撤掉取消；须先冲销其全部退货）
node app.ts -d ./data reverse R4 --orig X1   # 冲销取消：移除有效取消量、恢复相应待收量
node app.ts -d ./data reverse R5 --orig T1   # 冲销退货：向原收货仓补回退货量、恢复有效到货

# 整批导入有序单据列表（按顺序生效，整批成败一致）
node app.ts -d ./data import --file ./docs.json

# 补货规则维护与跨仓补货建议（先用可调拨实存，不足再建议采购；只读）
node app.ts -d ./data rule set P1 --wh W1 --min 5 --target 20
node app.ts -d ./data rule list
node app.ts -d ./data replenish
node app.ts -d ./data rule delete P1 --wh W1

# 补货方案：按当前建议冻结保存、查看、一次性落单
node app.ts -d ./data plan save PL1 --transfer P1:W2:W1:T1 --purchase P1:W1:PO9:华东五金
node app.ts -d ./data plan show PL1
node app.ts -d ./data plan list
node app.ts -d ./data plan execute PL1

# 整案撤回已执行方案：为每条调拨指定冲销单号、为每张采购指定取消单号（逐一对应）
node app.ts -d ./data plan withdraw W1 --plan PL1 --transfer-rev T1:R9 --purchase-cancel PO9:X9

# 余量查询（指定仓库或各仓）
node app.ts -d ./data balance P1
node app.ts -d ./data balance P1 --wh W2

# 流水查询（按商品和/或仓库，按提交顺序，含冲销反向变动与原单冲销状态）
node app.ts -d ./data flow --product P1
node app.ts -d ./data flow --wh W2

# 期间库存对账报表（只读；起点不含、终点含，可按商品/仓库筛选）
node app.ts -d ./data recon
node app.ts -d ./data recon --from D2 --to A1 --product P1
node app.ts -d ./data recon --to D3 --wh W1
```

## 命令行入口与调用说明

- 无参数、`--help`、`-h`：显示应用名与完整帮助，退出码 0。
- 未知命令或非法参数：向标准错误报错，退出码 2。对写命令，缺少必需参数、未知
  选项、导入文件结构非法等仅凭命令行即可判断的用法/格式错误，以及
  `STOCKROOM_LOCK_WAIT_MS` 等待配置非法，都在**取得写入机会之前**判定（退出码
  2），不创建数据目录或协调文件、不等待；数量格式非法等纯命令行业务拒绝同样在
  等待前以退出码 1 返回。库存余量、采购待收、编号占用等状态校验仍在取得写入
  机会、读到最新状态之后完成。
- 业务拒绝（重复编号、缺货、溢出、单据内容冲突、非法冲销等）或数据损坏/保存失败：
  向标准错误报错，退出码非 0（1）。等待写入机会超时也以退出码 1 结束（错误为
  “数据目录正忙”），本请求不留下任何变动。
- 全局选项 `-d, --data <目录>` 指定数据目录，默认 `./.stockroom`；
  数据文件为目录内的 `stockroom.json`，首次写入时自动创建。
- 也可执行 `npm link` 后使用 `stockroom` 命令（等价于 `node app.ts`）。

## 主要规则

- 商品编号、名称、单据编号、仓库标识均去除首尾空白后使用，不能为空；标识区分大小写。
- 商品编号唯一，重复登记被拒绝且不覆盖原资料。
- 入库增加目标仓余量，出库减少来源仓余量；调拨同时减来源仓、增目标仓，两仓不能相同。
- 数量必须为正安全整数；同单同商品明细先合并，再校验足量与安全整数上溢。
- 任一明细不合法则**整单拒绝**，所有库存保持原状（不部分生效）。
- 入库/出库/调拨/盘点/到货/取消/退货/采购转单/冲销/方案撤回请求单据编号在同一数据目录内共用全局唯一编号空间：相同业务
  内容重复提交返回原结果、不重复变动；同编号不同内容或不同业务拒绝；失败提交不占用编号。
  采购单编号独立于此空间，允许与上述单据同名。去重记录、采购进度、转单关联、冲销关系与库存、流水、
  结果一起持久化。
- 流水记录单据编号、类型、涉及仓库、数量及变动前后余量；调拨/冲销调拨两端可凭同一
  单据编号追溯；盘点/冲销盘点流水记录账面量、实盘量与差额（含零差额），差额正负及
  零变动与前后余量一致；到货/冲销到货流水额外记录采购单编号，到货冲销流水标注原到货单；
  退货/冲销退货流水额外记录采购单编号与原到货单编号，冲销退货流水标注原退货单。

## 整单盘点规则

- 命令：`count <单据编号> --wh <仓库> --item <商品编号:预期账面量:实盘量> [...]`，
  每张盘点单针对一个仓库、至少一种已登记商品；两种数量均为非负安全整数，
  同商品重复出现拒绝（不像入出库那样合并）。
- 首次提交先逐项核对当前余量与预期账面量（未发生变动的商品仓库组合账面量为零），
  任一不符**整单拒绝**并说明冲突商品及当前量；全部相符才把列出的商品校正为实盘量，
  未列出的商品及其他仓库不变。
- 差额 = 实盘量 - 账面量，可增、可减、可为零；全零差额仍记为成功单据并逐项追加流水。
- 幂等：同编号同内容（明细顺序无关）重放只返回原提交结果，即使余量已改变或盘点已
  被冲销也不再核对、不再生效；同编号不同内容或其他业务拒绝；失败不占用编号，
  调整输入后可重试。
- 成功输出各商品的预期账面量、实盘量、差额及校正前后余量。

## 整单冲销规则

- 命令：`reverse <冲销单编号> --orig <原单编号>`，只能冲销**已成功**的原始入库、
  出库、调拨、盘点、到货、取消、退货单；原单不存在、冲销单本身、已被成功冲销的原单均
  不能产生新的冲销，每张原单最多成功冲销一次。
- 冲销在**当前余量**上应用原单的相反变动，不恢复为原单提交前的绝对余量，也不删除
  原单之后的其他业务：
  - 冲销入库：从原目标仓扣回数量；
  - 冲销出库：向原来源仓补回数量；
  - 冲销调拨：从原调入仓扣回、向原调出仓补回；
  - 冲销盘点：在当前余量上减去原盘点差额（不恢复原账面绝对值）；零差额不改余量，
    但仍记录冲销关系与流水；
  - 冲销到货：从采购单收货仓扣回原数量并减少有效到货量，相应数量重新待收
    （不撤掉取消）；**有未冲销退货的到货单禁止冲销**，相关退货全部冲销后可按原
    规则冲销到货；
  - 冲销取消：移除该取消单的有效取消量、恢复相应待收量，不改库存、不产生库存流水；
  - 冲销退货：向原收货仓当前余量补回原退货量、恢复有效到货，不撤销后续业务。
- 数量取原单同商品合并后的明细。任一商品扣回不足，或补回后余量超出安全整数范围，
  或盘点冲减后为负/溢出，或冲销退货后“有效到货 + 有效取消”超过订购量，则整单拒绝、
  所有仓库与商品保持原状；失败不占用冲销单编号、不标记原单，条件改善后可用同一编号重试。
- 幂等：成功冲销的同编号、同原单请求重放，返回原冲销结果，即使余量已变化也不再
  变动；同编号改指其他原单或其他业务一律拒绝。原库存单据冲销后按原内容重放，仍只
  返回它最初的提交结果，不会重新生效。
- 成功输出各明细数量及操作前后余量，并在流水中追加反向变动条目（关联原单与冲销单
  编号）；`flow` 按商品/仓库可看到完整历史、原流水顺序及原单的冲销状态。
- 库存、流水、冲销关系和重放结果一起保存，保存（临时文件原子替换）成功后才报告
  成功，重启后全部限制仍成立；业务拒绝或保存失败均不改变已提交状态。

## 采购单与分批到货

- 登记命令：`po register <采购编号> --supplier <供应商名称> --wh <收货仓> --item <商品编号:订购量> [...]`，
  至少一种**已登记**商品，订购量为正安全整数，同商品重复明细先合并（合并溢出拒绝）。
- 采购单含编号、供应商名称、收货仓及各商品订购量；**登记只记录订购信息，不改动任何库存**，
  登记成功后内容不可修改。采购编号独立于库存单据编号空间，允许与入库/到货/冲销单同名；
  同号同内容（供应商、收货仓、合并后订购量一致，明细顺序无关）重放返回原登记结果且
  **不重置到货进度**，同号不同内容拒绝；失败不占编号。
- 到货命令：`arrival <到货单编号> --po <采购编号> --item <商品编号:到货量> [...]`，
  收货仓取采购单登记的收货仓，到货量为正安全整数、同商品先合并；可分多次提交，每次只
  收部分商品，但**只能收采购单内商品**，库存并入该收货仓。
- 各商品“有效到货 + 本次到货”不得超过扣除有效取消后的待到货量
  （**有效到货 = 未冲销到货 − 未冲销退货**；待到货量 = 订购量 - 有效到货量 - 有效取消量）；
  任一明细非法、商品不在单内、超收或入仓后余量超出安全整数范围，**整单拒绝**、不占到货单编号。
  出入库、调拨、盘点等其他库存业务不影响采购进度；普通入库不能事后绑定采购。
- 到货单与入库/出库/调拨/盘点/取消/冲销单**共用全局唯一编号空间**（采购编号不在此列）。
  同号且同采购单、同合并数量重放返回原结果——即使采购已收齐、库存已变化或该到货单已
  被冲销，也不重新核对、不再变动；同号不同内容或其他业务拒绝；失败不占编号。
- 到货成功逐项输出本次数量、库存变动前后量、未冲销累计到货量与待到货量，并追加带
  采购单编号的“到货”流水。
- 取消命令：`cancel <取消单编号> --po <采购编号> --item <商品编号:取消量> [...]`，
  取消未到货数量。商品必须在该采购单内，取消量为正安全整数、同商品先合并（合并溢出
  拒绝），明细顺序无关；可分次取消部分商品。**有效取消量只计未冲销取消单**；任一商品
  本次取消量超过当前待到货量，**整单拒绝**、不占取消单编号。成功只减少待收承诺，
  **不改原订购内容、库存或库存流水**。取消单与库存/到货/冲销单共用编号空间；同号同
  采购同合并数量重放返回原结果——即使进度已变化或该取消已冲销，也不重新校验、不再
  生效；同号不同内容或其他业务拒绝。取消结果逐商品说明本次数量、有效取消与待到货量。
- 取消单可被 `reverse <冲销单编号> --orig <取消单编号>` 整单冲销：移除其有效取消量、
  恢复相应待收量，不改库存及后续业务。每张取消单最多冲销一次，冲销单不可冲销；
  成功冲销重放只返回原结果，同冲销编号改指其他原单或编号冲突拒绝。采购登记重放
  不会清除取消记录。
- 到货可被 `reverse <冲销单编号> --orig <到货单编号>` 整单冲销：从当前收货仓扣回原
  数量、把该到货单从有效到货中剔除，已收齐采购相应数量重新待收（不撤掉取消）；
  不撤销其后的其他业务。**有未冲销退货的到货单禁止冲销**，相关退货全部冲销后可按
  原规则冲销到货。
  任一商品当前余量不足扣回则整单拒绝、不改进度、不登记冲销关系，同号可重试；每张到货单
  最多冲销一次，冲销单不可冲销；原到货单与成功冲销重放均只返回原结果。
- 退货命令：`return <退货单编号> --arrival <原到货单编号> --item <商品编号:退货量> [...]`，
  针对一张**已成功且未冲销**的原到货单做部分退货；采购单与收货仓取原到货，只能退原到货
  明细内商品，退货量为正安全整数、同商品先合并（合并溢出拒绝，明细顺序无关）。各商品本次
  退货量不得超过“原到货量 − 该到货单关联的未冲销退货量”，并从**原收货仓当前余量**扣减；
  超退、缺货或明细非法**整单拒绝**、不占退货单编号。退货抵减有效到货，相应数量重新待到货、
  **等待补收**；不改订购与取消。退货单与库存/到货/取消/冲销单共用编号空间；同号同原到货
  同合并数量重放返回原结果——即使进度已变化、该退货或原到货已冲销，也不重新校验、不再
  生效；同号不同内容或其他业务拒绝；失败不占编号。退货成功逐项输出本次数量、库存变动前后
  量、有效到货与待到货量，并追加带采购单编号与原到货单编号的“退货”流水。
- 退货可被 `reverse <冲销单编号> --orig <退货单编号>` 整单冲销：向原收货仓当前余量补回
  原退货量、恢复有效到货（待到货相应回落），不撤销后续业务。补回后库存溢出，或恢复后
  “有效到货 + 有效取消”超过订购量，则整单拒绝、不登记冲销关系，同号可重试；每张退货单
  最多冲销一次，冲销单不可冲销；原退货单与成功冲销重放均只返回原结果。
- 查询：`po show <采购编号>` 输出供应商、收货仓、各商品订购/有效到货/有效退货/有效取消/
  待到货量及仍待收（未到货、部分到货）与已结清（收齐、含取消结清）状态——取消、退货均
  不计作到货、不会误报收齐；并列出到货单、取消单、退货单与冲销单的关联。无取消、无退货
  记录的采购单保持原有展示。
  `po list` 列出全部采购单汇总。
  `flow --product/--wh` 中的到货/退货及各自冲销流水带采购单编号与原单编号，可按商品或
  仓库追溯采购、原到货、退货及冲销，方向与余量一致。
- 进度精度：有效到货 = 未冲销到货总量 − 未冲销退货总量，待到货 = 订购量 − 有效到货 −
  有效取消。反复退货、补收下累计到货或退货可超过 9007199254740991（安全整数上限），
  进度累计、校验与展示一律按精确整数计算，合计与记录枚举顺序无关，不因中间累计舍入而
  改变净量或误拒净进度合法的业务；有效退货合计超过安全整数范围时仍显示完整十进制整数。
  每笔订购/到货/退货/取消（同单合并后）仍为正安全整数，仓库余量仍为非负安全整数。

## 采购待收转单与整单冲销

- 转单命令：`po-transfer <转单编号> --orig <原采购编号> --dest <新目的采购编号>
  --supplier <供应商> --wh <收货仓> --item <商品编号:转出量> [...]`，用于重新安排
  待收商品的供应商或收货仓。至少一项原单内商品，数量为正安全整数、同商品重复明细
  先合并（合并溢出拒绝），明细顺序无关。
- 提交校验：原采购必须存在；目的采购编号必须**未被任何采购占用**——即使已有内容
  完全相同的采购单也拒绝，不接管、不续用；各商品转出量不得超过原单**当前待收量**，
  任一不符**整单拒绝**、不占用转单与目的采购编号，调整后可用同号重试。
- 成功效果：**同时**减少原单待收并新建一张目的采购单——转出量计入原单**有效取消**
  （原订购与有效到货不变），目的订购量等于转出量、初始**全量待收**。目的单是一张
  普通采购单，可正常到货、取消或**再转单**。全程**不改库存、不产生库存流水**。
- 净进度口径：待收 = 订购 − 有效到货 − 有效取消；有效到货 = 未冲销到货 − 未冲销
  退货；有效取消 = 未冲销取消单 + 本单作为原单的未冲销转出量（目的单若来源转单已
  冲销，则其全部订购量计为取消）。操作、`po show`/`po list`、`replenish` 待到货
  合计与补货方案快照一律按此**精确净进度**（BigInt）计算，超安全整数合计仍完整显示。
- 编号空间：转单与库存、到货、取消、退货、冲销单**共用**单据编号空间；采购编号
  （原单与目的单）独立。同转单编号、同全部内容（原单、目的单、供应商、收货仓、
  合并转出量）重放返回原结果，**不重新校验、不再生效、不改写文件**——即使进度已
  改变或该转单已冲销；改任一字段或改做其他业务一律拒绝；失败不占用本次新编号。
- 成功结果逐商品说明转出数量及原单、目的单操作前后的待收。
- 整单冲销：`reverse <冲销单编号> --orig <转单编号>`。仅当**目的单所有商品仍全量
  待收**（有效到货与有效取消均为零）才允许；通过先冲销目的单上的退货、到货等历史
  业务已合法恢复全量待收的，也允许冲销。
- 冲销成功**仅**移除本转单在原单形成的有效取消（原单待收相应回升），并把目的单
  全部订购量计为取消、待收归零；保留两张采购单与全部历史，**不撤销**其后业务，
  不改库存、不产生库存流水。转出造成的原单待收减少与目的单关闭**不能**作为取消单
  单独冲销，只能由转单冲销整体处理。每张转单最多冲销一次；冲销单不可冲销。
- 同冲销单编号、同原单重放返回原冲销结果，不重新校验、不再生效（即使目的单已不再
  全量待收）；改指其他原单或编号冲突拒绝。
- `po show` 展示真实净进度、本单作为原单的转出与作为目的单的转入记录、对应目的/
  原采购单及冲销单关联；取消、转单关闭均不误报“收齐”（报“已结清（含取消）”）。

## 跨仓补货建议

- 规则维护：`rule set <商品编号> --wh <仓库> --min <下限> --target <目标>` 为**已登记**
  商品与仓库设置唯一补货规则（仓库无需登记，无库存记录视为零）；`rule list` 查看全部规则，
  `rule delete <商品编号> --wh <仓库>` 删除。下限与目标均为非负安全整数且**下限小于目标**；
  同（商品, 仓库）组合再次 `set` **整体替换**原规则。规则随数据文件原子保存，保存成功后
  才报告成功，失败保留已提交状态，重启及其他命令保存后规则仍有效。
- 建议查询：`replenish` 取当前**已提交状态**逐组合计算，不写文件、不改变库存或采购，
  同状态结果一致；库存、到货、取消、退货及冲销后按新状态重算。
  - 待到货合计：收货仓为本仓的**所有**采购单（不限供应商）中该商品的待到货量之和，
    待到货 = 订购 − 有效到货 − 有效取消（有效到货 = 未冲销到货 − 未冲销退货，
    有效取消只计未冲销取消；到货不会重复计入待收）。
  - 预计量 = 本仓实存 + 待到货合计（其他仓库存不计入）；预计量**不高于下限**才触发，
    缺口 = 目标 − 预计量。
  - 按商品分别分配调拨：同商品**其他已配置仓**实存超过自身目标的部分可供调拨
    （待收不可调；未配置仓既不产生需求，也不提供调拨）。缺货仓、来源仓各按标识升序，
    依次为每个缺货仓从来源取量，直到补足缺口或来源耗尽再处理下一仓；整份建议对来源的
    累计分配不超过可供量。**剩余缺口即采购量**（可为零），未触发组合无补货。
  - 逐组合输出商品、仓库、下限、目标、实存、待到货合计、预计量与触发情况；触发项列出
    各调拨来源及数量、调拨合计与采购量（包括零采购）。无规则或无缺货时明确提示。
  - 合计、比较与分配按精确整数计算，超安全整数合计完整十进制显示。

## 补货方案：保存、查看与一次性落单

- 保存：`plan save <方案编号> --transfer <商品>:<来源仓>:<目标仓>:<子单编号> [...]
  --purchase <商品>:<收货仓>:<子单编号>:<供应商> [...]` 按**当前补货建议**的触发、来源
  分配与采购数量冻结完整方案——数量一律取建议值，不能自行改量；必须为每条调拨指定
  子单编号、为每个**正采购缺口**指定子单编号与供应商（零采购不建采购子单，多指定或
  少指定均拒绝）；无触发建议时拒绝保存。保存只登记方案与快照，**不改库存、采购与
  流水，也不占用任何子单编号**。
- 方案编号使用**独立编号空间**（可与单据、采购单同名）。同号同保存输入重放返回原
  方案、不重新计算（明细顺序无关）；同号改输入拒绝。保存时冻结**涉及商品的全部
  补货规则**及这些配置仓的**实存与待到货合计**快照（待到货按订购 − 有效到货 −
  有效取消精确计算，超安全整数合计不舍入）。
- 执行：`plan execute <方案编号>` 首次执行前按值核对快照——规则增删改、实存或
  待到货合计任一变化**整案拒绝**并说明差异（不替换为新建议；无关商品变化不使方案
  过期；快照与现状不一致只表示过期，不算数据损坏）。核对通过后检查全部拟用子单
  编号未被对应空间占用（调拨子单与库存/到货/取消/退货/冲销单同空间，采购子单用
  采购编号空间；**即使内容相同也拒绝，不接管已有单据**），再按冻结内容生成普通
  调拨单（实际减来源、增目标）与采购单（仅登记待收承诺）。全部子单、方案关联、
  执行状态与原结果**一次原子保存**后才报成功；缺货、溢出或任一子单拒绝均不留下
  本次库存、采购、流水、编号或执行标记，方案保留待执行，条件改善后可重试。
- 已执行方案再次 `plan execute` 只返回原落单结果，不再核对快照、不再生效、不改写
  文件；其子单后来被冲销、取消或到货也不重建。真实结果可通过 `balance`、`flow`、
  `po show` 读回，`plan show` 可追溯对应子单编号。
- 查看：`plan show <方案编号>` 展示调拨来源、目标仓、商品、数量、采购供应商、子单
  编号及待执行/已执行/已撤回状态；`plan list` 列出全部方案。
- 无 `plans` 字段的旧数据直接可用并保留历史结果；损坏方案或已执行方案的子单关联
  断裂（子单不存在或内容与冻结不符）视为损坏数据，拒读拒写。入口格式错误报标准
  错误退出 2，业务拒绝及读写失败退出 1。

## 补货方案整案撤回

- 命令：`plan withdraw <请求编号> --plan <方案编号>
  --transfer-rev <调拨子单编号>:<冲销单号> [...]
  --purchase-cancel <采购子单编号>:<取消单号> [...]`，整案撤回**已执行且未撤回**
  的补货方案，取消尚未履行的补货安排。为每条调拨子单指定一个冲销单号、为每张
  采购子单指定一个取消单号，与方案子单**逐一对应**——无缺漏、多余或重复项，
  指定顺序无关。只有调拨或只有采购的方案同样支持。
- 编号空间：请求编号与全部新子单号（冲销单号、取消单号）同入库/出库/调拨/盘点/
  到货/取消/退货/采购转单/冲销单**共用全局唯一编号空间**，彼此不得重号；方案、
  采购编号仍各自独立。首次撤回**不接管已占编号**——即使内容相同也拒绝；撤回
  请求本身**不可冲销**。
- 撤回条件按**当前精确净进度**判断，不核对保存快照，规则变化不阻止撤回：各调拨
  子单须**未冲销**；各采购子单所有商品须**全量待收**（有效到货与有效取消均为
  零）；历史业务经合法操作（如冲销到货、冲销取消）恢复此状态也允许。
- 成功效果：在**当前余量**上冲销全部调拨（从原调入仓扣回、向原调出仓补回，追加
  普通冲销流水），并取消全部采购的**完整订购量**、待收归零（取消不改库存及库存
  流水）；**不恢复库存快照，不删除原单或后续业务**。
- 缺货、库存溢出、进度不符或编号冲突均**整案拒绝**并说明子单和原因：本次库存、
  进度、流水、编号、冲销关系及撤回标记全部不保留，失败不占编号，可同号重试。
  全部变化、关联、撤回状态及原结果**一次原子保存**后才报成功；读写失败保留已
  提交状态。
- 每案最多成功撤回一次。同请求编号、同方案及子单映射重放返回原结果，不再校验、
  生效或改写文件；改内容或改做其他业务拒绝。撤回后 `plan execute` 及原子单重放
  仍返回原成功结果，不重新落单。撤回产生的新取消单可按普通规则冲销，但方案保持
  已撤回，不能再次撤回。
- 结果逐子单说明数量及库存或待收前后值；`plan show`/`plan list` 展示撤回状态与
  撤回请求、原子单、新子单关联，`balance`、`flow`、`po show` 读回真实结果。
  无 `planWithdrawals` 字段的旧数据按无撤回加载并保留原结果；撤回关联缺失或
  内容不符（方案未标记、映射缺漏、新子单不存在或内容不符）视为损坏数据，拒读
  拒写，重启后全部限制仍成立。

## 期间库存对账报表

- 命令：`recon [--from <起点单据编号>] [--to <终点单据编号>] [--product <商品编号>] [--wh <仓库>]`，
  生成可追溯的期间库存对账报表。**只读**：读取与反复查询均不创建或改写数据、历史结果及关联。
- 期间边界：起点表示该单**全部流水完成后**的状态（期间**不含**起点），终点**包含**该单全部流水；
  同一单作两端为**空期间**；不指定起点从**零库存**开始，不指定终点**截至当前**。
  边界按**首次提交顺序**（流水序号）比较，不按编号排序；起点晚于终点或单据不存在则拒绝（退出 1）。
- 边界仅接受**已成功且有库存流水**的单据：冲销单（冲销取消单除外，其无库存流水）与零差额
  盘点可用；只有采购登记或取消记录的编号不可用（它们不产生库存流水）；采购编号空间独立，
  **同名采购单不干扰**库存单定位。标识去首尾空白后非空、区分大小写，含冒号及 `__proto__`
  等名称均可定位与筛选。
- 筛选：`--product`、`--wh` 可单独或同时指定，不筛选则覆盖全库。**先确定全局边界再筛选**，
  不拆开多商品单据或调拨两端。
- 组合展示：每个（商品， 仓库）组合展示**期初、期间增加与减少的非负合计、净变动、期末**
  （恒满足 期初 + 增加 − 减少 = 期末），并按**业务类型及是否冲销**分别列出带符号净变动小计。
  调拨按各仓实际方向统计（调入为增、调出为减）；到货、退货及反向冲销计入实存，采购登记、
  取消及其冲销不计入；盘点按实际差额统计，**零差额仍保留追溯**；已冲销原单保留当时变动，
  冲销只在其发生的期间计入，不倒改原期间。
- 期间流水：按提交顺序列出期间内匹配流水，显示商品、仓库、单据类型与编号、带符号变动、
  前后量及采购单、原到货单、冲销关联；**原单冲销状态以终点时刻为准**，终点之后的冲销不影响
  历史报表。
- 组合按商品、仓库标识升序；展示期初或期末非零及期间有流水的组合，无匹配时明确提示。
  **逐商品汇总**所选仓库的期初、增加、减少、净变动与期末；累计量及合计用精确整数，
  超过安全整数仍完整十进制显示。
- 出报表前核对完整库存流水的**余量连续性**、**调拨两端完整性**及**末笔余量与当前实存一致**；
  发现不一致明确报错（退出 1），不输出部分报表，也不自动修复。
- 参数格式错误退出 2；边界业务拒绝、数据损坏或读取失败退出 1，均报标准错误。

## 整批导入

- 入口：`import --file <单据列表.json>`（与其他命令一样可配合 `-d/--data` 指定数据目录）。
- 文件为 UTF-8 JSON：根节点必须是**有序单据对象数组，至少一项**；按数组顺序处理，
  新单据以此前各项生效后的余量核对并计算，流水中的先后顺序与列表顺序一致。
- 仅允许十种业务，字段如下（所有标识去除首尾空白后非空、区分大小写）：

  | 业务 | type | 必需字段 | 明细字段 |
  | --- | --- | --- | --- |
  | 入库 | `in` | `id`、`wh`、`items` | `product`、`qty` |
  | 出库 | `out` | `id`、`wh`、`items` | `product`、`qty` |
  | 调拨 | `transfer` | `id`、`from`、`to`、`items` | `product`、`qty` |
  | 盘点 | `count` | `id`、`wh`、`items` | `product`、`expected`、`actual` |
  | 采购 | `po` | `id`、`supplier`、`wh`、`items` | `product`、`qty`（订购量） |
  | 到货 | `arrival` | `id`、`po`、`items` | `product`、`qty`（到货量） |
  | 取消 | `cancel` | `id`、`po`、`items` | `product`、`qty`（取消量） |
  | 退货 | `return` | `id`、`arrival`、`items` | `product`、`qty`（退货量） |
  | 采购转单 | `po-transfer` | `id`、`orig`、`dest`、`supplier`、`wh`、`items` | `product`、`qty`（转出量） |
  | 冲销 | `reverse` | `id`、`orig` | 无（原单可以是到货单、取消单、退货单、采购转单，数量取原单合并后的明细） |

- 商品必须已登记；入出库、调拨、采购、到货、取消、退货、采购转单的 `qty` 为正安全整数，同商品明细先合并再
  校验；盘点的 `expected`/`actual` 均为非负安全整数，同商品重复出现拒绝；调拨两仓不能相同，转单原采购与
  目的采购不能相同。
- 后项可以使用前项入库/到货所得库存；到货、取消、转单可引用导入前已登记或本列表此前登记的采购单
  （转单的目的采购由本项新建，其编号必须此前未被任何采购占用），
  退货可引用导入前已成功或本列表此前成功的到货单，其超收/超取消/超退/超转出校验针对此前各项生效后的
  采购进度；盘点核对的是此前各项之后的账面量；冲销可指向
  导入前已成功的原单（含到货单、取消单、退货单、采购转单）或列表中此前的新原单；冲销转单时该转单须为
  此前成功项（原采购与被冲销转单均须此前成功）、且其目的单仍全量待收，**尚未出现且未保存的原单不可引用**；
  冲销到货同样回补采购待到货量，冲销取消同样恢复待收量，冲销退货同样补回库存并恢复有效到货，
  冲销转单同样移回原单待收并关闭目的单；
  冲销单不可冲销，每张原单最多冲销一次。
- 编号与单条命令共用唯一空间（入库/出库/调拨/盘点/到货/取消/退货/采购转单/冲销），采购编号独立、可与这些
  单据同名，不产生批次编号：导入前已有或本列表此前出现的“同编号同内容”项均只返回原结果，
  不重新核对库存或采购进度、不追加流水——即使原单已冲销也不重新生效。普通单据比较类型、
  仓库及合并后的商品数量（明细顺序无关）；盘点比较仓库及各商品两种数量；采购比较供应商、
  收货仓及订购量；到货、取消比较采购编号及合并数量；退货比较原到货单编号及合并数量；
  转单比较原采购、目的采购、供应商、收货仓及合并转出量；
  冲销比较原单编号。同编号不同内容或不同业务整批拒绝。
- 整批成功须全部项通过，有新生效单据时整批一次性保存；**全部重复时不改写数据**。
  任一项格式不合法、缺货、账面冲突、超收、超取消、超退、溢出、编号冲突或非法冲销，整批拒绝并指出
  位置（第几项）和原因：此前已保存的单据不撤销，本批新库存、采购进度、流水、编号与冲销
  关系均不保留，纠正后可复用这些新编号。
- 文件无法读取、已有数据损坏或保存失败均不改变已提交状态，也不报告部分成功。
  文件格式或参数错误报标准错误、退出 2；业务拒绝及读写失败退出 1。
- 成功时按列表顺序逐项输出编号、“首次生效/重复（导入前已存在/本批此前已出现）”
  状态及对应提交结果；新流水按列表顺序追加，保留既有历史与冲销关联，可通过
  `flow` 读回，重启后查询、去重与冲销限制仍成立。

## 多进程写入协调

- 同一数据目录可同时在多个终端办理业务：所有可能改变数据的命令（商品登记、
  入库/出库/调拨/盘点、冲销、采购登记、到货、取消、退货、采购转单、补货规则
  维护、方案保存/执行/撤回、整批导入）执行前先取得该目录的写入机会，**取得后
  才读取最新已提交状态**，完成业务校验与去重，全部变化一次原子保存后才报成功。
  并发请求互不覆盖：独立请求的最终结果等价于某个完整串行执行顺序，流水序号与
  该顺序一致；首次创建数据目录的并发写入同样协调。导入、方案执行与撤回始终
  作为完整事务：整项通过才一次原子保存，任一项失败本批不留任何变动。
- **协调方式（UNIX 域套接字）**：写入机会由数据目录内的协调套接字
  `.stockroom.json.lock` 表示，占用者在独立工作线程中持有监听套接字并立即接受
  连接，互斥由内核维护。相对、绝对及符号链接路径指向同一目录时共用同一个协调
  点；不同数据目录各有各的协调点，互不阻塞。协调套接字路径过长（超过系统 UNIX
  域路径上限）时自动改放到系统临时目录，并按数据目录真实路径的哈希命名，同一
  目录的各种写法仍共用一个协调点。
- **等待上限与配置**：等待写入机会默认最多 10 秒，可用环境变量
  `STOCKROOM_LOCK_WAIT_MS` 设为非负安全整数毫秒（`0` 表示仅立即尝试一次，拿不到
  就立刻以退出码 1 结束）；配置为空以外的非法值（非数字、负数、小数、超出安全
  整数范围）在**等待之前**报标准错误并以退出码 2 结束，绝不会被转换成无限等待。
  超时向标准错误报告“数据目录正忙”并以退出码 1 结束，本次请求不留下任何库存、
  进度、流水、编号或方案标记，也不影响其他进程已提交的结果，可直接重试。
- **存活进程绝不被接管**：占用状态由内核的“是否有监听者”决定，而非文件年龄或
  锁内容。占用者进程只要存活——即使它在建立协调套接字之后、写完任何持有者信息
  之前暂停，或办理业务期间暂停超过两秒——其工作线程仍持续接受探活连接，等待者
  只能等待，绝不会因文件年龄、内容不完整或暂停过久而被接管。
- **异常退出自动恢复（串行回收）**：占用者进程异常退出（如被 SIGKILL）时，内核
  自动关闭其监听；后续写请求连续两次 connect 失败确认无监听者后，把遗留套接字
  用同目录短名**改名移走并再次 connect 复核**（短名保证不超过系统路径长度；一旦
  复核到仍有存活监听立即改名还原），确认无主才删除并在原协调点自行占用。多个
  请求同时发现遗留占用时，最终唯一监听者由内核裁决，它们只能**一个接一个**串行
  取得写入机会，不会有两个请求同时办理。回收者不会移走另一个请求刚取得的占用；
  每个请求结束或失败时也只关闭自己的监听、绝不改名或删除协调路径，因此不会
  删掉后继请求刚建立的占用。全程无需手工删除任何文件。
- **提交前后异常退出的语义**：数据保存为“写唯一临时文件 + 原子 rename”。异常
  退出发生在原子替换之前的，本次业务变动完全不生效、不占用编号，遗留临时内容
  不算提交；发生在替换之后的，完整提交已保留（即使来不及输出成功），重试按已有
  结果去重并返回原结果。遗留临时文件不会被当作已提交数据；取得写入机会者只清理
  已退出进程的临时文件与回收副本，绝不清除仍存活请求的临时文件。业务拒绝、保存
  失败或超时都不保留本请求新增状态，也不影响别人的提交。
- 只读查询（balance、flow、recon、replenish、product/po/rule/plan 的
  list/show）不创建协调文件，写入期间只会读到完整的旧状态或完整的新状态。

## 数据兼容与安全

- 旧版数据文件（无冲销/采购/到货/取消/退货/采购转单/补货规则/补货方案/方案撤回字段）无需重新登记或导入即可直接读写，原有单据的去重
  记录与提交结果继续生效，旧入库不会被推断为到货，无取消记录的采购单按无取消处理、无退货记录
  的到货单按无退货处理、无转单字段按无转单处理、无补货规则字段按无规则处理、无方案字段按无方案处理、
  无撤回字段按无撤回处理；首次使用相应功能后自动补齐新字段。
- 采购单、到货单、取消单、退货单、采购转单、补货规则与冲销关系连同库存、进度、流水一起原子保存：保存成功后才报告成功，
  重启后超收/超取消/超退/超转出限制、共用编号空间、冲销唯一性、有未冲销退货的到货单禁止冲销、
  转单冲销须目的单仍全量待收、到货/取消/退货/转单/冲销关联、补货规则等规则仍成立；损坏数据
  （含无效取消或退货关联、未冲销累计退货超原到货量、有效到货与有效取消合计超订购导致的负待到货量、
  损坏采购转单或目的采购/冲销关联——目的单缺失或内容不符、来源转单不存在、转单冲销时目的单并非
  全量待收、冲销转单携带库存流水等、
  非法补货规则、损坏补货方案或已执行方案的子单关联断裂、方案撤回关联缺失或内容
  不符——方案未标记或标记不一致、子单映射缺漏或多余、新冲销单/取消单不存在或
  内容与撤回不符）拒绝启动，不会被当作空库或部分结果覆盖。
- 所有记录容器使用 null 原型对象，`constructor`、`__proto__`、`toString` 等名称可
  正常作为商品、仓库、采购/到货/冲销单据编号使用，不会串改其他记录或保存非法余量。
- 数据文件损坏、无法读取或结构校验不通过时明确报错退出，不会当作空库覆盖。
