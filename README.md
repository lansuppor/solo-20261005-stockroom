# stockroom

本地多仓库存台账命令行工具。使用 TypeScript + Node.js 24 编写，无外部运行依赖，
数据以单个 JSON 文件保存在本地；支持指定数据目录，不同目录互不影响。

## 运行环境

- Node.js 24（直接执行 `.ts`，无需编译或安装依赖）

## 快速开始

```sh
# 登记商品
node app.ts -d ./data product add P1 螺丝
node app.ts -d ./data product add P2 螺母
node app.ts -d ./data product list

# 入库 / 出库 / 跨仓调拨（每单可含多个 --item，同商品重复明细自动合并）
node app.ts -d ./data in D1 --wh W1 --item P1:10 --item P2:3
node app.ts -d ./data out D2 --wh W1 --item P1:4
node app.ts -d ./data transfer D3 --from W1 --to W2 --item P1:2 --item P1:3

# 整单盘点校正（先核对账面再按实盘校正；同商品重复明细拒绝）
node app.ts -d ./data count C1 --wh W1 --item P1:6:8 --item P2:3:3

# 采购单登记（不改库存）与分批到货、部分退货、进度查询
node app.ts -d ./data po register PO1 --supplier 华东五金 --wh W1 --item P1:10 --item P2:5
node app.ts -d ./data arrival A1 --po PO1 --item P1:4 --item P1:3   # 同商品先合并为 7
node app.ts -d ./data arrival A2 --po PO1 --item P1:3 --item P2:5   # 可分次、可部分到货
node app.ts -d ./data cancel X1 --po PO1 --item P2:5                # 取消未到货数量（只减少待收承诺，不改库存）
node app.ts -d ./data return T1 --arrival A1 --item P1:2            # 部分退货：从原收货仓扣减，退回后等待补收
node app.ts -d ./data po show PO1
node app.ts -d ./data po list

# 整单冲销已成功的入库/出库/调拨/盘点/到货/取消/退货单（独立冲销单编号 + 被冲销原单编号）
node app.ts -d ./data reverse R1 --orig D1
node app.ts -d ./data reverse R2 --orig C1
node app.ts -d ./data reverse R3 --orig A1   # 冲销到货：扣回库存并重开待到货量（不撤掉取消；须先冲销其全部退货）
node app.ts -d ./data reverse R4 --orig X1   # 冲销取消：移除有效取消量、恢复相应待收量
node app.ts -d ./data reverse R5 --orig T1   # 冲销退货：向原收货仓补回退货量、恢复有效到货

# 整批导入有序单据列表（按顺序生效，整批成败一致）
node app.ts -d ./data import --file ./docs.json

# 补货规则维护与跨仓补货建议（先用可调拨实存，不足再建议采购；只读）
node app.ts -d ./data rule set P1 --wh W1 --min 5 --target 20
node app.ts -d ./data rule list
node app.ts -d ./data replenish
node app.ts -d ./data rule delete P1 --wh W1

# 余量查询（指定仓库或各仓）
node app.ts -d ./data balance P1
node app.ts -d ./data balance P1 --wh W2

# 流水查询（按商品和/或仓库，按提交顺序，含冲销反向变动与原单冲销状态）
node app.ts -d ./data flow --product P1
node app.ts -d ./data flow --wh W2
```

## 命令行入口与调用说明

- 无参数、`--help`、`-h`：显示应用名与完整帮助，退出码 0。
- 未知命令或非法参数：向标准错误报错，退出码 2。
- 业务拒绝（重复编号、缺货、溢出、单据内容冲突、非法冲销等）或数据损坏/保存失败：
  向标准错误报错，退出码非 0（1）。
- 全局选项 `-d, --data <目录>` 指定数据目录，默认 `./.stockroom`；
  数据文件为目录内的 `stockroom.json`，首次写入时自动创建。
- 也可执行 `npm link` 后使用 `stockroom` 命令（等价于 `node app.ts`）。

## 主要规则

- 商品编号、名称、单据编号、仓库标识均去除首尾空白后使用，不能为空；标识区分大小写。
- 商品编号唯一，重复登记被拒绝且不覆盖原资料。
- 入库增加目标仓余量，出库减少来源仓余量；调拨同时减来源仓、增目标仓，两仓不能相同。
- 数量必须为正安全整数；同单同商品明细先合并，再校验足量与安全整数上溢。
- 任一明细不合法则**整单拒绝**，所有库存保持原状（不部分生效）。
- 入库/出库/调拨/盘点/到货/取消/退货/冲销单据编号在同一数据目录内共用全局唯一编号空间：相同业务
  内容重复提交返回原结果、不重复变动；同编号不同内容或不同业务拒绝；失败提交不占用编号。
  采购单编号独立于此空间，允许与上述单据同名。去重记录、采购进度、冲销关系与库存、流水、
  结果一起持久化。
- 流水记录单据编号、类型、涉及仓库、数量及变动前后余量；调拨/冲销调拨两端可凭同一
  单据编号追溯；盘点/冲销盘点流水记录账面量、实盘量与差额（含零差额），差额正负及
  零变动与前后余量一致；到货/冲销到货流水额外记录采购单编号，到货冲销流水标注原到货单；
  退货/冲销退货流水额外记录采购单编号与原到货单编号，冲销退货流水标注原退货单。

## 整单盘点规则

- 命令：`count <单据编号> --wh <仓库> --item <商品编号:预期账面量:实盘量> [...]`，
  每张盘点单针对一个仓库、至少一种已登记商品；两种数量均为非负安全整数，
  同商品重复出现拒绝（不像入出库那样合并）。
- 首次提交先逐项核对当前余量与预期账面量（未发生变动的商品仓库组合账面量为零），
  任一不符**整单拒绝**并说明冲突商品及当前量；全部相符才把列出的商品校正为实盘量，
  未列出的商品及其他仓库不变。
- 差额 = 实盘量 - 账面量，可增、可减、可为零；全零差额仍记为成功单据并逐项追加流水。
- 幂等：同编号同内容（明细顺序无关）重放只返回原提交结果，即使余量已改变或盘点已
  被冲销也不再核对、不再生效；同编号不同内容或其他业务拒绝；失败不占用编号，
  调整输入后可重试。
- 成功输出各商品的预期账面量、实盘量、差额及校正前后余量。

## 整单冲销规则

- 命令：`reverse <冲销单编号> --orig <原单编号>`，只能冲销**已成功**的原始入库、
  出库、调拨、盘点、到货、取消、退货单；原单不存在、冲销单本身、已被成功冲销的原单均
  不能产生新的冲销，每张原单最多成功冲销一次。
- 冲销在**当前余量**上应用原单的相反变动，不恢复为原单提交前的绝对余量，也不删除
  原单之后的其他业务：
  - 冲销入库：从原目标仓扣回数量；
  - 冲销出库：向原来源仓补回数量；
  - 冲销调拨：从原调入仓扣回、向原调出仓补回；
  - 冲销盘点：在当前余量上减去原盘点差额（不恢复原账面绝对值）；零差额不改余量，
    但仍记录冲销关系与流水；
  - 冲销到货：从采购单收货仓扣回原数量并减少有效到货量，相应数量重新待收
    （不撤掉取消）；**有未冲销退货的到货单禁止冲销**，相关退货全部冲销后可按原
    规则冲销到货；
  - 冲销取消：移除该取消单的有效取消量、恢复相应待收量，不改库存、不产生库存流水；
  - 冲销退货：向原收货仓当前余量补回原退货量、恢复有效到货，不撤销后续业务。
- 数量取原单同商品合并后的明细。任一商品扣回不足，或补回后余量超出安全整数范围，
  或盘点冲减后为负/溢出，或冲销退货后“有效到货 + 有效取消”超过订购量，则整单拒绝、
  所有仓库与商品保持原状；失败不占用冲销单编号、不标记原单，条件改善后可用同一编号重试。
- 幂等：成功冲销的同编号、同原单请求重放，返回原冲销结果，即使余量已变化也不再
  变动；同编号改指其他原单或其他业务一律拒绝。原库存单据冲销后按原内容重放，仍只
  返回它最初的提交结果，不会重新生效。
- 成功输出各明细数量及操作前后余量，并在流水中追加反向变动条目（关联原单与冲销单
  编号）；`flow` 按商品/仓库可看到完整历史、原流水顺序及原单的冲销状态。
- 库存、流水、冲销关系和重放结果一起保存，保存（临时文件原子替换）成功后才报告
  成功，重启后全部限制仍成立；业务拒绝或保存失败均不改变已提交状态。

## 采购单与分批到货

- 登记命令：`po register <采购编号> --supplier <供应商名称> --wh <收货仓> --item <商品编号:订购量> [...]`，
  至少一种**已登记**商品，订购量为正安全整数，同商品重复明细先合并（合并溢出拒绝）。
- 采购单含编号、供应商名称、收货仓及各商品订购量；**登记只记录订购信息，不改动任何库存**，
  登记成功后内容不可修改。采购编号独立于库存单据编号空间，允许与入库/到货/冲销单同名；
  同号同内容（供应商、收货仓、合并后订购量一致，明细顺序无关）重放返回原登记结果且
  **不重置到货进度**，同号不同内容拒绝；失败不占编号。
- 到货命令：`arrival <到货单编号> --po <采购编号> --item <商品编号:到货量> [...]`，
  收货仓取采购单登记的收货仓，到货量为正安全整数、同商品先合并；可分多次提交，每次只
  收部分商品，但**只能收采购单内商品**，库存并入该收货仓。
- 各商品“有效到货 + 本次到货”不得超过扣除有效取消后的待到货量
  （**有效到货 = 未冲销到货 − 未冲销退货**；待到货量 = 订购量 - 有效到货量 - 有效取消量）；
  任一明细非法、商品不在单内、超收或入仓后余量超出安全整数范围，**整单拒绝**、不占到货单编号。
  出入库、调拨、盘点等其他库存业务不影响采购进度；普通入库不能事后绑定采购。
- 到货单与入库/出库/调拨/盘点/取消/冲销单**共用全局唯一编号空间**（采购编号不在此列）。
  同号且同采购单、同合并数量重放返回原结果——即使采购已收齐、库存已变化或该到货单已
  被冲销，也不重新核对、不再变动；同号不同内容或其他业务拒绝；失败不占编号。
- 到货成功逐项输出本次数量、库存变动前后量、未冲销累计到货量与待到货量，并追加带
  采购单编号的“到货”流水。
- 取消命令：`cancel <取消单编号> --po <采购编号> --item <商品编号:取消量> [...]`，
  取消未到货数量。商品必须在该采购单内，取消量为正安全整数、同商品先合并（合并溢出
  拒绝），明细顺序无关；可分次取消部分商品。**有效取消量只计未冲销取消单**；任一商品
  本次取消量超过当前待到货量，**整单拒绝**、不占取消单编号。成功只减少待收承诺，
  **不改原订购内容、库存或库存流水**。取消单与库存/到货/冲销单共用编号空间；同号同
  采购同合并数量重放返回原结果——即使进度已变化或该取消已冲销，也不重新校验、不再
  生效；同号不同内容或其他业务拒绝。取消结果逐商品说明本次数量、有效取消与待到货量。
- 取消单可被 `reverse <冲销单编号> --orig <取消单编号>` 整单冲销：移除其有效取消量、
  恢复相应待收量，不改库存及后续业务。每张取消单最多冲销一次，冲销单不可冲销；
  成功冲销重放只返回原结果，同冲销编号改指其他原单或编号冲突拒绝。采购登记重放
  不会清除取消记录。
- 到货可被 `reverse <冲销单编号> --orig <到货单编号>` 整单冲销：从当前收货仓扣回原
  数量、把该到货单从有效到货中剔除，已收齐采购相应数量重新待收（不撤掉取消）；
  不撤销其后的其他业务。**有未冲销退货的到货单禁止冲销**，相关退货全部冲销后可按
  原规则冲销到货。
  任一商品当前余量不足扣回则整单拒绝、不改进度、不登记冲销关系，同号可重试；每张到货单
  最多冲销一次，冲销单不可冲销；原到货单与成功冲销重放均只返回原结果。
- 退货命令：`return <退货单编号> --arrival <原到货单编号> --item <商品编号:退货量> [...]`，
  针对一张**已成功且未冲销**的原到货单做部分退货；采购单与收货仓取原到货，只能退原到货
  明细内商品，退货量为正安全整数、同商品先合并（合并溢出拒绝，明细顺序无关）。各商品本次
  退货量不得超过“原到货量 − 该到货单关联的未冲销退货量”，并从**原收货仓当前余量**扣减；
  超退、缺货或明细非法**整单拒绝**、不占退货单编号。退货抵减有效到货，相应数量重新待到货、
  **等待补收**；不改订购与取消。退货单与库存/到货/取消/冲销单共用编号空间；同号同原到货
  同合并数量重放返回原结果——即使进度已变化、该退货或原到货已冲销，也不重新校验、不再
  生效；同号不同内容或其他业务拒绝；失败不占编号。退货成功逐项输出本次数量、库存变动前后
  量、有效到货与待到货量，并追加带采购单编号与原到货单编号的“退货”流水。
- 退货可被 `reverse <冲销单编号> --orig <退货单编号>` 整单冲销：向原收货仓当前余量补回
  原退货量、恢复有效到货（待到货相应回落），不撤销后续业务。补回后库存溢出，或恢复后
  “有效到货 + 有效取消”超过订购量，则整单拒绝、不登记冲销关系，同号可重试；每张退货单
  最多冲销一次，冲销单不可冲销；原退货单与成功冲销重放均只返回原结果。
- 查询：`po show <采购编号>` 输出供应商、收货仓、各商品订购/有效到货/有效退货/有效取消/
  待到货量及仍待收（未到货、部分到货）与已结清（收齐、含取消结清）状态——取消、退货均
  不计作到货、不会误报收齐；并列出到货单、取消单、退货单与冲销单的关联。无取消、无退货
  记录的采购单保持原有展示。
  `po list` 列出全部采购单汇总。
  `flow --product/--wh` 中的到货/退货及各自冲销流水带采购单编号与原单编号，可按商品或
  仓库追溯采购、原到货、退货及冲销，方向与余量一致。
- 进度精度：有效到货 = 未冲销到货总量 − 未冲销退货总量，待到货 = 订购量 − 有效到货 −
  有效取消。反复退货、补收下累计到货或退货可超过 9007199254740991（安全整数上限），
  进度累计、校验与展示一律按精确整数计算，合计与记录枚举顺序无关，不因中间累计舍入而
  改变净量或误拒净进度合法的业务；有效退货合计超过安全整数范围时仍显示完整十进制整数。
  每笔订购/到货/退货/取消（同单合并后）仍为正安全整数，仓库余量仍为非负安全整数。

## 跨仓补货建议

- 规则维护：`rule set <商品编号> --wh <仓库> --min <下限> --target <目标>` 为**已登记**
  商品与仓库设置唯一补货规则（仓库无需登记，无库存记录视为零）；`rule list` 查看全部规则，
  `rule delete <商品编号> --wh <仓库>` 删除。下限与目标均为非负安全整数且**下限小于目标**；
  同（商品, 仓库）组合再次 `set` **整体替换**原规则。规则随数据文件原子保存，保存成功后
  才报告成功，失败保留已提交状态，重启及其他命令保存后规则仍有效。
- 建议查询：`replenish` 取当前**已提交状态**逐组合计算，不写文件、不改变库存或采购，
  同状态结果一致；库存、到货、取消、退货及冲销后按新状态重算。
  - 待到货合计：收货仓为本仓的**所有**采购单（不限供应商）中该商品的待到货量之和，
    待到货 = 订购 − 有效到货 − 有效取消（有效到货 = 未冲销到货 − 未冲销退货，
    有效取消只计未冲销取消；到货不会重复计入待收）。
  - 预计量 = 本仓实存 + 待到货合计（其他仓库存不计入）；预计量**不高于下限**才触发，
    缺口 = 目标 − 预计量。
  - 按商品分别分配调拨：同商品**其他已配置仓**实存超过自身目标的部分可供调拨
    （待收不可调；未配置仓既不产生需求，也不提供调拨）。缺货仓、来源仓各按标识升序，
    依次为每个缺货仓从来源取量，直到补足缺口或来源耗尽再处理下一仓；整份建议对来源的
    累计分配不超过可供量。**剩余缺口即采购量**（可为零），未触发组合无补货。
  - 逐组合输出商品、仓库、下限、目标、实存、待到货合计、预计量与触发情况；触发项列出
    各调拨来源及数量、调拨合计与采购量（包括零采购）。无规则或无缺货时明确提示。
  - 合计、比较与分配按精确整数计算，超安全整数合计完整十进制显示。

## 整批导入

- 入口：`import --file <单据列表.json>`（与其他命令一样可配合 `-d/--data` 指定数据目录）。
- 文件为 UTF-8 JSON：根节点必须是**有序单据对象数组，至少一项**；按数组顺序处理，
  新单据以此前各项生效后的余量核对并计算，流水中的先后顺序与列表顺序一致。
- 仅允许九种业务，字段如下（所有标识去除首尾空白后非空、区分大小写）：

  | 业务 | type | 必需字段 | 明细字段 |
  | --- | --- | --- | --- |
  | 入库 | `in` | `id`、`wh`、`items` | `product`、`qty` |
  | 出库 | `out` | `id`、`wh`、`items` | `product`、`qty` |
  | 调拨 | `transfer` | `id`、`from`、`to`、`items` | `product`、`qty` |
  | 盘点 | `count` | `id`、`wh`、`items` | `product`、`expected`、`actual` |
  | 采购 | `po` | `id`、`supplier`、`wh`、`items` | `product`、`qty`（订购量） |
  | 到货 | `arrival` | `id`、`po`、`items` | `product`、`qty`（到货量） |
  | 取消 | `cancel` | `id`、`po`、`items` | `product`、`qty`（取消量） |
  | 退货 | `return` | `id`、`arrival`、`items` | `product`、`qty`（退货量） |
  | 冲销 | `reverse` | `id`、`orig` | 无（原单可以是到货单、取消单、退货单，数量取原单合并后的明细） |

- 商品必须已登记；入出库、调拨、采购、到货、取消、退货的 `qty` 为正安全整数，同商品明细先合并再
  校验；盘点的 `expected`/`actual` 均为非负安全整数，同商品重复出现拒绝；调拨两仓不能相同。
- 后项可以使用前项入库/到货所得库存；到货、取消可引用导入前已登记或本列表此前登记的采购单，
  退货可引用导入前已成功或本列表此前成功的到货单，其超收/超取消/超退校验针对此前各项生效后的
  采购进度；盘点核对的是此前各项之后的账面量；冲销可指向
  导入前已成功的原单（含到货单、取消单、退货单）或列表中此前的新原单，**尚未出现且未保存的原单不可引用**；
  冲销到货同样回补采购待到货量，冲销取消同样恢复待收量，冲销退货同样补回库存并恢复有效到货；
  冲销单不可冲销，每张原单最多冲销一次。
- 编号与单条命令共用唯一空间（入库/出库/调拨/盘点/到货/取消/退货/冲销），采购编号独立、可与这些
  单据同名，不产生批次编号：导入前已有或本列表此前出现的“同编号同内容”项均只返回原结果，
  不重新核对库存或采购进度、不追加流水——即使原单已冲销也不重新生效。普通单据比较类型、
  仓库及合并后的商品数量（明细顺序无关）；盘点比较仓库及各商品两种数量；采购比较供应商、
  收货仓及订购量；到货、取消比较采购编号及合并数量；退货比较原到货单编号及合并数量；
  冲销比较原单编号。同编号不同内容或不同业务整批拒绝。
- 整批成功须全部项通过，有新生效单据时整批一次性保存；**全部重复时不改写数据**。
  任一项格式不合法、缺货、账面冲突、超收、超取消、超退、溢出、编号冲突或非法冲销，整批拒绝并指出
  位置（第几项）和原因：此前已保存的单据不撤销，本批新库存、采购进度、流水、编号与冲销
  关系均不保留，纠正后可复用这些新编号。
- 文件无法读取、已有数据损坏或保存失败均不改变已提交状态，也不报告部分成功。
  文件格式或参数错误报标准错误、退出 2；业务拒绝及读写失败退出 1。
- 成功时按列表顺序逐项输出编号、“首次生效/重复（导入前已存在/本批此前已出现）”
  状态及对应提交结果；新流水按列表顺序追加，保留既有历史与冲销关联，可通过
  `flow` 读回，重启后查询、去重与冲销限制仍成立。

## 数据兼容与安全

- 旧版数据文件（无冲销/采购/到货/取消/退货/补货规则字段）无需重新登记或导入即可直接读写，原有单据的去重
  记录与提交结果继续生效，旧入库不会被推断为到货，无取消记录的采购单按无取消处理、无退货记录
  的到货单按无退货处理、无补货规则字段按无规则处理；首次使用相应功能后自动补齐新字段。
- 采购单、到货单、取消单、退货单、补货规则与冲销关系连同库存、进度、流水一起原子保存：保存成功后才报告成功，
  重启后超收/超取消/超退限制、共用编号空间、冲销唯一性、有未冲销退货的到货单禁止冲销、
  到货/取消/退货/冲销关联、补货规则等规则仍成立；损坏数据
  （含无效取消或退货关联、未冲销累计退货超原到货量、有效到货与有效取消合计超订购导致的负待到货量、
  非法补货规则）拒绝启动，不会被当作空库或部分结果覆盖。
- 所有记录容器使用 null 原型对象，`constructor`、`__proto__`、`toString` 等名称可
  正常作为商品、仓库、采购/到货/冲销单据编号使用，不会串改其他记录或保存非法余量。
- 数据文件损坏、无法读取或结构校验不通过时明确报错退出，不会当作空库覆盖。
